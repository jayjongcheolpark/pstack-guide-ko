# 이 책을 읽는 방법

## 누구를 위한 책인가

Cursor에서 에이전트에게 실제 코드를 맡겨 본 엔지니어를 위한 책입니다. pstack을 설치했지만 스킬이 51개나 되어 어디서 시작할지 막막한 분, 특정 스킬이 어떻게 동작하는지 정확히 알고 싶은 분을 염두에 두었습니다. Cursor 채팅, Git, GitHub PR을 써 본 경험을 가정합니다.

## 구성

| 부 | 내용 |
| --- | --- |
| 시작하기 | pstack의 목적과 설계 아이디어, 설치와 첫 사용, 모델 설정, `poteto-help` |
| 진입점 | 대부분의 작업이 거쳐 가는 `poteto-mode`와 그 플레이북 23개 |
| 이해하기 | `how`, `why`, `teach`, `recall` |
| 설계하기 | `architect`, `arena`, `swarm`, `figure-it-out`, 그리고 `principle-*` 스킬 24개 |
| 고치고 검증하기 | `tdd`, `blast-radius`, `interrogate`, `benchmark-checklist`, 검증 스킬 2개 |
| 글과 코드 정리 | `unslop`, `technical-writing`, `no-comments`, `typescript-best-practices` |
| 나만의 방식과 유틸리티 | `automate-me`, `reflect`, `correct`, `show-me-your-work`, `bro` |
| 자동화 | `make-bot-ui`와 benny 자동화 팩 |
| 실전 | 밤새 돌리기, 레시피와 함정 |

부록에는 스킬 빠른 참조표, 용어집, 스킬 선택 흐름도, 저작권 표기가 있습니다.

원본의 사용 안내서(`docs/guide`)는 설정, 라우팅, 이해, 설계, 빌드와 정리, 검증(verification)과 배포, 밤새 돌리기, 원칙(principle), 나만의 방식, 레시피의 열 장으로 되어 있습니다. 이 책은 스킬을 주제별로 묶는 구성을 택했고, 안내서의 흐름은 각 부에 나눠 담았습니다.

두 가지는 처음 구상에서 바꿨습니다. `poteto-mode`는 다른 스킬 대부분을 호출하는 허브이고 분량도 가장 커서, 설계하기의 한 항목으로 두지 않고 시작하기 바로 다음에 독립된 부로 세웠습니다. PR을 다루는 흐름은 별도 스킬이 아니라 `poteto-mode`의 플레이북(`opening-a-pr`, `babysit`, `shipping`)이라서 진입점 부에서 다룹니다.

## 스킬 절의 구조

스킬 하나는 다음 순서로 설명합니다. 작은 스킬은 일부를 합칩니다.

1. `원문` 링크: 고정된 커밋의 GitHub 주소
2. 한 줄 요약
3. 언제 쓰는가: 트리거 문구와 적용 조건
4. 동작 방식: 단계별 설명
5. 사용 예
6. 함정과 주의점: 원문이 직접 경고하는 항목
7. 관련 스킬

## 원본의 내용과 이 책이 덧붙인 내용

플레이북 절과 원칙 절의 뒷부분에는 원본을 읽고 정리한 부분과 이 책의 저자가 덧붙인 부분이 섞여 있습니다. 구분하는 방법은 다음과 같습니다.

- 플레이북 절의 "흐름도"는 플레이북 파일의 단계, 분기, 중단 조건을 그린 것입니다. 원문에 없는 단계는 넣지 않았습니다.
- "단계별 산출물", "실패, 중단, 모호할 때", "호출하는 스킬과 스크립트"는 원문이 서술한 것을 표와 목록으로 다시 정리한 것입니다. 원문이 정하지 않은 경우는 정하지 않았다고 적었습니다.
- "예시 (이 책의 저자가 만든 것, 원본에 없음)"로 시작하는 점선 블록은 이 책의 저자가 만든 요청, 코드, 대화입니다. 원본의 문구도 아니고 pstack이 한 말도 아닙니다.
- "해설 (이 책의 해석, 원본에 없음)"은 원문이 말하지 않은 해석입니다.

## 표기 규칙

- 스킬 이름, 명령어, 코드, 파일 경로, 식별자는 원문 그대로 영어로 씁니다. 예: `poteto-mode`, `/tdd`, `SKILL.md`.
- 영어 용어는 처음 나올 때 한국어 풀이를 붙입니다. 이후에는 [용어집](glossary.md)의 표기를 씁니다.
- 한국어 단어 하나가 원문의 서로 다른 영어 용어를 나타낼 수 있는 곳에는 그 단어 바로 뒤에 영어를 괄호로 붙여 `원칙(principle)`, `규칙(rule)`처럼 씁니다. 장마다 처음 나올 때 붙이고, 같은 장에서 뜻이 바뀌면 바뀐 곳마다 다시 붙입니다. 어떤 단어가 어떤 영어 용어에 해당하는지는 용어집의 [일대일로 옮겨지지 않는 용어](glossary.md#terms-not-one-to-one) 표에 있습니다.
- 코드 블록의 `text` 블록은 에이전트에게 입력하는 문장의 예입니다. 원문의 예시는 소문자 위주의 구어체 영어입니다. 이 책은 뜻을 유지한 한국어 예시를 쓰거나, 원문 그대로 인용할 때는 영어로 둡니다.
- 슬래시 명령어는 Cursor 채팅에서 입력하는 이름입니다. `/how`는 `how` 스킬을 부릅니다.

## 읽는 순서

처음이라면 시작하기 부와 진입점 부를 차례로 읽으십시오. 그다음은 필요한 부를 골라 읽어도 됩니다. 어떤 스킬을 골라야 할지 모르겠으면 Cursor에서 `/poteto-help`를 쓰거나 [부록의 선택 흐름도](decision-flow.md)에서 시작하십시오.
